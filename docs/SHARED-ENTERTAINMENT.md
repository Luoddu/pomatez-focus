# 跨电脑娱乐额度与倒计时：接入方案（NAS待准备）

## 当前交付状态

P0-POMO-095 的逐日图表已在独立分支实现并进行本地验证，尚未发布。共享额度服务、桌面客户端和浏览器配套已完成本机候选实现；服务尚未部署，不能把本机图表或偏好同步描述成跨电脑互锁。任务状态只看TASK-P0-POMO-095.md。

## 需要统一的状态

- 以同一个用户与同一个时区定义的日期为边界，保存每日总额度、已消费/已预留额度、实际使用记录和同步覆盖情况。
- 冷静等待截止时间与娱乐放行截止时间均保存绝对时刻。客户端展示剩余时间，不在换机、启动或重连时重新生成完整时长。
- 云端须原子核准额度或采用能证明总额守恒的分配协议；仅“先读取余额再写回”不能处理两台设备同时领取。现有飞书append-only偏好版本协议不是额度扣减事务。
- 设备在获取新的娱乐使用许可前核对共享状态。账号切换、缓存陈旧、鉴权失败、未知提交结果、服务不可达均不能退回一份全新的本地额度。
- 用户已确认：离线停止发放新娱乐额度、已开始倒计时继续，工作应用不受影响。有效短时许可已经从全局预留，最长20秒，到期即停止娱乐。
- 已有本机专注目标/工作日严格限制与共享额度取较严格结果，不因接入云端放宽旧限制。

## 统计口径

单机图表来自既有AW确认后的活动区间。7/30日按午夜拆分；重叠区间去重；缺失不等于0。当前仅展示“本机已采集记录”。共享汇总按设备/日期合并区间，处理重叠区间并显式提示可能缺失设备，不把未收到上报当零使用。不上传视频标题、完整URL或私人任务名称，最小数据为分类与时间区间。

## 云端接入的必要决定

需要用户给出可部署的位置（已有云服务器/托管平台，或允许先评估选型），无需把密钥发到聊天。随后冻结官方版本、原子存储机制、鉴权与本机Secret存储方案、费用/频率、回滚与故障退出，再补执行卡并实现。未知云目标时不自行新建账号、付费、开放端口、安装后台服务或写真实飞书表。

飞书官方Bitable v1新增记录文档声明写冲突与client_token幂等，但这不等价于带条件的余额更新。来源：https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create 。若用户希望仅用飞书，需进一步核实固定API是否具备所需核准能力；不能用多次轮询冒充原子互锁。

## 最终正反验收

两设备先后/同时领取、重启/换机/重连、同ID丢回执重试、跨日、调系统时钟、网络分区和额度用尽均不能重领或延长截止时间；正常剩余额度、正常工作和合法次日额度仍可用。必须先在合成隔离环境跑客户端到服务完整链路，再在获准的实际云目标与两台电脑验收，才能报告跨电脑已生效。
